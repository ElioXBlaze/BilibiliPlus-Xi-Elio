系统音量和网页音量要同步，调一个都动网页做不到。Apple 官方：iOS/iPadOS 上 <video>.volume 只读且恒为 1，音量始终由用户物理键控制；硬件音量键不触发 volumechange；navigator.audioSession 只有 type/state、没有音量属性；AVAudioSession.outputVolume 是原生 API，网页无权访问如实说明边界：脚本不写 volume、不读系统音量、不用 Web Audio GainNode 绕过（会破坏 iOS 的 per-element bless 模型）。在 volume 可写的环境（桌面 Safari 等）才把记忆值写回 <video>；iPad 上只控制 muted，二者不打架。另从 B 站音量控件 value / aria-valuenow 补记「用户意图音量」，覆盖 iPad 上收不到 volumechange 的情况
自动解除静音有点迟钝，开始播放一两秒才有声音Apple《为 Safari 传送视频内容》原文：元素只有不含音轨或 muted=true 才能无手势自动播放，「在没有用户手势的情况下取消了静音，播放就会暂停」。旧版把 unmute 放在 play().then() + setTimeout(60ms) 里，既不在手势回调栈内、又多等一轮，还得等用户在播放页再点一次① 优先「带声音 + 记忆音量」起播：用户点开视频本身就是手势，Safari 允许 → 画面和声音同时开始，零延迟；② 被 NotAllowedError 拒绝立刻回退静音起播；③ 静音起播时，在第一次真实手势的回调里同步 muted=false，不 setTimeout、不 then、不 play()。删掉 play().then() + 60ms 整条旧链路

v1.4 强制 页面 fetch(url, {credentials:'include'}) 优先，并依次尝试 https://www.bilibili.com（主站同站，最稳）与 https://api.bilibili.com；只有两条都失败才退回扩展通道并显式补 Cookie 头。日志里会写「成功通道 www.bilibili.com」。

⑤ 必须说清楚的边界

这部分决定你会不会踩坑，建议认真看一遍。

关于「真正铺满全屏」⚠️
先说清楚上一版为什么坏了：webkitEnterFullscreen（iPad 原生视频全屏）会把画面和键盘一起交给系统播放器，网页里的弹幕层、控制栏、keydown 监听全部不再参与 —— 所以「按 F 没弹幕」「F 退不出」是必然结果，不是偶发 bug。而那个 fixed 到 100dvh 的黑底容器又盖在整页之上，Esc 退出原生全屏后留在页面上，就成了「整页黑屏没声」。

v1.2 的方案：不再自己造全屏。F 只是点一下 B 站自己的全屏按钮，B 站管状态机；脚本检测到全屏态后，只给 <video> 和它的直接父级加 width/height/object-fit inline 样式，退出时按属性快照还原。不 fixed 容器、不改 body、不加黑底覆盖层、不动祖先链 —— 结构上不可能再留黑屏。

填充模式：默认「智能」看视频比例 —— 横屏用 cover 消灭 16:9 在 iPad 4:3 屏上的上下黑边；竖屏用 contain 保留完整画面（不裁掉人脸和字幕），两侧水印底改纯黑。Shift+F 可强制切「一律裁切」或「一律适应」。

仍然做不到：Safari 的地址栏、标签栏和底部手势条是系统外壳，任何网页脚本都隐藏不了；竖屏视频也做不到「既完整又铺满」，二选一。想要系统级真全屏可以手动绑「原生播放器全屏」命令，但那样弹幕和所有快捷键都会失效，脚本会先弹确认。
关于「按 F 没弹幕 / 退不出 / 整页黑屏 / 关掉后 F 没反应」v1.2 已修
这四个症状是同一个错误的四种表现，逐条对照见本页顶部「v1.2 全屏逻辑推倒重写」表格。

现在：弹幕 —— 不调原生播放器，B 站弹幕层照常渲染；退出 —— 键盘始终归网页管，再按 F 或按 Esc 都能退；黑屏 —— 零全屏 CSS + 属性快照还原， Startup 还会主动清旧版残留类；关掉后 F 没反应 —— F 与 🧹 复位被列为「永远可用」命令，不受总开关和铺满开关影响。

万一还是卡住：按 Shift+R 或点工具条 🧹，会立刻还原 video 样式并清掉旧版类名；再不行刷新页面即可。
关于「回车后不断跳、搜不了」v1.3 零导航
上一版为什么没解决：三种「落地方式」（移动版 / 页内 / 桌面域）本质都是要打开 search.bilibili.com 或 m.bilibili.com/search，而 iPad Safari 请求桌面网站时这两个域会来回 302，Safari 直接报「发生了太多重定向」。另外「直接点 B 站官方搜索框搜」走的是 B 站自己的提交逻辑，脚本的快捷键浮层根本管不到。

v1.3 的做法：彻底不打开任何搜索页面。改调官方搜索接口 x/web-interface/wbi/search/type（带 WBI 签名，失败自动退回旧接口），把结果画在自己的浮层里；点结果只打开 www.bilibili.com/video/BV… 主站同域。同时在捕获阶段拦掉 B 站原生搜索的 submit、指向搜索域的链接点击、以及 window.open，所以无论用快捷键还是直接点官方搜索框，都不会再跳。

⚠️ 必须手动做一次：Safari 会把过期的重定向信息缓存在「网站数据」里。若之前已经崩过，即使脚本不再发起跳转，首次仍可能报错。按 Apple 官方支持：设置 → Safari 浏览器 → 高级 → 网站数据 → 移除 bilibili.com → 刷新页面（会退出登录，重新登录一次）。脚本只能拦新跳转，清不掉浏览器缓存的旧重定向。
关于「音量记忆 / 系统音量能不能同步 / 解除静音迟钝」v1.6.3
记忆：只要你在 B 站音量条 / 滚轮 / M 键调整过音量，数值（含 0%）就记下来，下一个视频、下一次打开都复用。MDN 明确 volumechange 在 volume 或 muted 变化时都会触发，所以脚本写回记忆值时用 applyingVolume 屏蔽，B 站初始化和第三方脚本用用户手势窗口过滤，避免「自己写回 0.8 又被当成用户调整」。

系统音量：Apple 官方说明 iOS/iPadOS 上 <video>.volume 只读且恒为 1，音量始终由用户物理键 / 控制中心控制，硬件音量键不触发 volumechange；navigator.audioSession 只有 type/state；AVAudioSession.outputVolume 是原生 API。网页脚本无法读取或设置系统音量，做不到「调一个另一个跟着动」。脚本在 iPad 上只控制 muted，不写 volume、不用 Web Audio GainNode 绕过（会破坏 iOS 的 per-element bless 模型）。在 volume 可写的桌面环境，记忆值会自动写回。

零延迟：旧版把 unmute 放在 play().then() + setTimeout(60ms) 里，Apple 明确「在没有用户手势的情况下取消静音，播放就会暂停」，所以既不安全又慢。v1.6.3 优先用「带声音 + 记忆音量」play()（用户点开视频即手势）→ 成功则画面与声音同时开始；被 NotAllowedError 拒绝才静音起播，并在第一次真实手势回调里同步 muted=false。
关于「自动播放后暂停不住 / 抽动两下才能暂停」v1.6.2 已修
不是 iPad Safari 的锅，是脚本自己抢播。旧版有三处「补播」：解除静音后 600ms 若暂停就回退静音重播、手势 pointerdown 里借机 play()、900ms 定时器与 20 秒重试链不认「用户主动暂停」。你点视频画面暂停时，前两处会把刚暂停的画面又拉起来，于是「抽动两下」。

v1.6.2 全部删除，改为一条硬规则：自动起播只负责「刚点开、从未播放过」的这一次。playing 事件一触发就按视频 key 记「已播放」并 stopAutoPlay() 清掉重试定时器；pause 事件一触发就记「用户主动暂停」并同样收手。统一入口 apAllowed() 之后对所有 play() 调用返回 false。当时的解除静音函数只做「关静音 + 设音量」，不再碰播放状态（v1.6.3 已把该函数收敛为 unmuteNow() 单一入口，并加入音量记忆 / 特性探测）。

所以刚进页面画面会自动静音跑起来，你点/滑一下恢复音量，之后任何暂停都是一次停住。换新视频会重新获得一次起播机会；点「🎬 立即尝试起播」可强制重跑一次，跑完仍立即收手。若怀疑脚本没收手，复制「📋 起播诊断」看 settled=true / retryTimer=false。
关于「按 R 显示刷新成功，但推荐没刷新」v1.6.1 已修
根因是只提示、不验证：旧版拿 [class*="refresh-btn"] 找到任意节点就 click()，然后无条件说「推荐已刷新」。在视频页可能点到的根本不是「换一换」，在首页也可能命中外层 div。

v1.6.1：限定首页 → 找可见的真实 button.roll-btn → 原生 click / 完整 pointer 事件序列 / 内部图标三级尝试 → 对比点击前后首屏 12 张卡片。只有列表真变了才报成功，否则明确说「已点击但列表没变化」并给出「📋 刷新诊断」。

视频页按 R：会提示「R 只在 B 站首页刷新推荐」，因为播放页右侧相关推荐没有换一换按钮。想刷推荐请先回首页。
关于「按 D 有提示但弹幕不变」v1.5 已修

v1.5 收敛到 .bpx-player-ctrl-btn.bpx-player-ctrl-danmaku-switch，等待挂载后点击前后各读一次状态；不变才依次尝试 input.click、完整 pointer 事件序列。公开脚本也只用原生 click()，不会无依据叠加合成事件（isTrusted=false 反而可能被忽略）。结果是四态之一：已切换并验证 / 点击成功但未验证状态 / 按钮未挂载 / 页面未提供可读状态，不再无条件说「弹幕已切换」。

关于「发弹幕显示成功却没发出去」v1.6 整体删除
这条链路连修几版仍不稳：自定义 x/v2/dm/post 提交在 iPad Safari + Stay 上受 Cookie、风控与分段 cid 影响，code=0 也不等于弹幕真的入库。

关于「选啥颜色都白色 / 字号没用 / 三连报账号未登录」v1.4 已修（历史）
根因不是你没登录。上一版把 POST 优先交给 GM_xmlhttpRequest，Safari / Stay 的扩展请求不共享页面 Cookie，B 站一律回「账号未登录」；脚本随即降级成「写原生输入框发默认白字」，而降级路径当时完全没同步颜色和字号 —— 所以「选啥都白色、字号无效」。

v1.4：页面 fetch(url,{credentials:'include'}) 优先，依次尝试 www.bilibili.com 与 api.bilibili.com，扩展通道只在两条都失败时兜底并补 Cookie 头。颜色（9 预设 + # 自定义 HEX + 🌈 大会员渐变 colorful=60001）、字号（12/18/25/36/45）、位置（1/5/4）都真正送进 x/v2/dm/post；即便降级到原生输入框，也会先同步样式。

注：v1.4 的「渐变权限不足自动降级重发」在 v1.5 已改为默认不自动降级（按查证建议：非会员遇 36718 应明确报错并保留用户选的颜色，不悄悄改色），可在「⌨ 快捷键」页手动打开该开关。

三连：archive/like/triple 一次完成赞 + 币 + 藏。没硬币或接口失败时自动补点赞 + 收藏（收藏优先查默认收藏夹走接口，拿不到就点 B 站自己的收藏按钮并尽力自动确认），不会因为没币整件失败。

仍需要网页已登录 B 站：脚本从本机 Cookie 读 bili_jct 做 CSRF 校验，不上传任何凭证。点「🔐 登录自检」可一眼看清 Cookie 是否可读、nav 是否判定已登录；若显示未登录，用 https://www.bilibili.com/ 重新登录并刷新。
关于「从别的网页回来快捷键就失效」v1.3 无条件夺回
原因：Safari 切回标签时会把焦点恢复到 B 站顶部搜索框，而脚本在输入框里必须让行，于是 R / D / S 全变成打字。v1.1 加了一个「2.5 秒内不夺回」的保护窗口，结果切回来的时机常常正好落在窗口里，等于没修。

v1.3 去掉了这个猜测：监听 visibilitychange / pageshow / focus / popstate，回来就把主文档和 Shadow DOM 里所有输入框无条件 blur 掉，并关掉输入类浮层，不用再点一下空白处。输入框聚焦时显示「⌨ 输入中 · Esc 恢复」徽标，任何位置按 Esc 也能立刻夺回。
关于「下载无水印」⚠️
B 站 playurl 返回的原始流通常不带平台水印，所以「下载即无水印」指的是不额外叠加，不是「去掉」什么。UP 主在剪辑时烧进画面的水印、平台对特定内容的版权标识，脚本不会也不应处理。

高清档普遍是 DASH：视频 m4s 与音频 m4s 分离，浏览器内合并需要 ffmpeg.wasm，长视频 / 4K 在 iPad 上很容易吃满内存，所以本套件分别列出直链，把合并交给桌面端或你自己的快捷指令：
ffmpeg -i video.m4s -i audio.m4s -c copy output.mp4 直链一般要求 Referer: https://www.bilibili.com/，直接粘进 Safari 地址栏可能 403；请用 Stay 下载管理器或支持自定义请求头的工具。

硬性不做的部分：不破解 WBI 签名、不绕过登录 / 大会员 / 充电专属 / 付费课程 / DRM / 地区限制，不批量抓取，不缓存可复用 Token。付费内容依平台协议仅供本人在平台内观看学习；下载也请遵守同样的范围，不要二次传播或商用。若接口返回权限不足，脚本会停下来告诉你原因。
关于截帧、快捷键与分区查询
截帧：CDN 若没有正确的 CORS 头，canvas 会被污染，toBlob 抛 SecurityError。脚本会先用离屏 video + crossOrigin=anonymous 重试，仍失败就明确提示改用 iPad 截屏组合键，绝不给一张空白图冒充成功。

快捷键：需要外接键盘。输入框、contenteditable、输入法组合态（keyCode 229）全部放行；系统组合键不 preventDefault。官方弹幕输入框的所有按键也完全放行。三连走官方接口，不依赖页面上真实存在的按钮；接口返回失败会如实提示原因（未登录 / 硬币不足），不会假装成功。

分区屏蔽：首页卡片常常不带 tid，脚本按 BV 号查一次 x/web-interface/view 并本机缓存（上限 600 条）。B 站接口收紧或返回 412 时自动降级为「卡片分区标签匹配」，可能漏判，但不会误杀知识区。所有规则存在本机，不上传、不读 Cookie。
一句话总结：1、2、3、4、6、7、8 完整可用。v1.6 把自定义发弹幕整套删掉、发弹幕恢复官方输入框（A / Shift+Enter 解绑），并重写了自动播放：iPad Safari 只允许静音起播，所以先把画面跑起来，你点 / 滑一下页面音量就恢复。弹幕显示开关 D 保留，三连（已确认可用）完全没动。5（下载）仍受版权、权限、DASH 分离和 iPad 下载能力约束，能做到的是「有权限的单文件直链 + 分离流直链 + 明确失败原因」，不是「一键破解下载器」。两点手动事项：清掉 Safari 里 bilibili.com 的网站数据（否则旧重定向缓存还会报错）；始终用 www.bilibili.com 访问并确认已登录。v1.6.1 还修好了 R 键「报成功却没刷新」：限定首页、找真实换一换按钮、核对首屏卡片真变了才报成功。v1.6.3 三条反馈都落地：音量「只要调整就记忆」并跨视频复用；解除静音改到真实手势回调里同步执行、不再迟钝 1~2 秒；按 Apple / WebKit / MDN 多源资料整体复核并清掉冗余代码（4 处 restoreVolume 收敛为 1、合并 autoPlayDone、删除 volumeTouched、去掉 900ms 重复起播调用、合并重复 M 按钮）。唯一做不到的如实说明：iPad Safari 的 volume 只读，网页无权读写系统音量，所以「调一个另一个跟着动」无法实现；脚本只控制静音开关，不制造假同步。v1.7 又补三处：被屏蔽的空白容器填上「与学习无关」；长按相反档键回 1× 原速；官方「长按右方向键 3×」全程不拦截，松开强制回 1× 而不是之前的档位（清 CFG.rate，换片也不写回）。v1.8 把搜索快捷键改成原生 toggle：按一下 S 自动唤出 B 站自己的「搜索历史 + 热搜」下拉（任何页面都能弹，多组选择器 + 展开按钮 + SPA 重试），再按一下关闭并复原焦点与输入内容；展开期间在捕获阶段优先接住第二次 S，不会把 S 打进搜索框。回车出结果仍是零导航浮层，不回 search 域。v1.8.1 又修两个实机 bug：播放页顶栏收起（不是全屏）时，先戳 B 站自己、放宽 input 查找、必要时临时亮出祖先链并完整还原，坚持用原生组件；右下工具条的 host 层级常驻最高、dock 改显式状态 + 同手势去重，二级菜单不再闪一下就消失。v1.9 把搜索拆成两套：S 有原生框用原生、没有就自动降级浮层；Shift+S 是独立浮层快捷键，深色原生风格、输入即出官方联想词、回车结果带七栏分类（计数来自 pageinfo.numResults），点结果仍只开主站合法 URL，零导航不变。v1.9.1 把设置面板拆成 8 页：功能开关集中在「⚙」页、历史改动折叠在「🕘」页，打开设置会自动收起右下二级工具条并排好层级，面板展开时全局快捷键让行，Esc / 点遮罩 / × 都能关。v1.9.2 再收敛为 4 页：删掉播放 / 快捷键 / 专注屏蔽 / 下载截帧 / 教程五个子项，全部设置与键位收进「⚙ 功能开关」，自检单开「🩺」页，功能页不再写版本号、只留一行简洁小字 —— 两版都只重排界面，没有改动任何命令与配置生效逻辑。若音量异常复制「📋 音量诊断」，自动播放异常复制「📋 起播诊断」看 settled，长按倍速异常复制「📋 倍速诊断」，设置面板异常（开关错位 / 点了没反应）：先在「⚙ 功能开关」页确认开关状态，再「🩺 自检」页复制诊断；所有开关都即时生效并自动保存。浮层异常复制「📋 浮层诊断」看 suggestChannel / channel / tab / count / lastError（联想词跨域被拦会静默降级，不影响搜索）；原生搜索异常复制「📋 搜索诊断」看 selector / forcedRevealed / forcedRestored / panelVisible / dockOpen 或点「🔄 重试唤出」，R 异常复制「📋 刷新诊断」再排障。

0️⃣ 打开设置后右侧还浮着二级菜单 → v1.9.1 已修：打开设置会自动收起 dock，遮罩 / 面板 / toast 层级已显式排好；若仍看到，刷新页面一次（旧样式缓存）。

6️⃣ 「复制诊断信息」导出日志（不含 Cookie / Token / 观看历史）。

为什么不会互相冲突

• 单实例守卫：重复注入直接退出。
• 单一命令总线：只有一个 keydown 捕获监听，不再各注册各的。
• 速率仲裁：只在本套件选档时写 playbackRate，B 站原生或其他脚本的改动只记录、不抢写。
• 共享 Observer：一个根观察器 + 分片扫描，不为倍速/分区/UP 各开一个。
• 软隐藏：加 class 不删节点，恢复瞬间完成。
• 样式隔离：面板在 Shadow DOM，页面样式全部 .bpe- 前缀且只在明确状态下用 !important。
